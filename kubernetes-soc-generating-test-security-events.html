Generating Test Security Events

Generate safe lab events that create useful SOC telemetry without teaching exploit behavior.

Kubernetes SOC Field Lab · Practical Security Operations

Domain alignment

Detection EngineeringKubernetes Security

Lab objective

Generate safe, benign events that help you practice alert review without teaching harmful behavior. The goal is telemetry, not exploitation.

Create demo namespace

kubectl create namespace soc-lab --dry-run=client -o yaml | kubectl apply -f -

Safe test event examples

  • Create and delete files inside a test container.
  • Run harmless shell commands in a test pod.
  • Start and stop a short-lived workload.
  • Access a demo web service with curl/wget from a toolbox pod.
  • Create a ConfigMap and inspect Kubernetes events.

Example: test workload activity

kubectl -n soc-lab create deployment soc-demo-web --image=nginx:latest
kubectl -n soc-lab get pods
kubectl -n soc-lab exec -it deploy/soc-demo-web -- /bin/sh -c "echo SOC lab test event > /tmp/soc-test.txt && cat /tmp/soc-test.txt"

Example: toolbox network request

kubectl -n soc-lab expose deployment soc-demo-web --port=80
kubectl -n soc-lab run soc-toolbox --image=busybox:latest --restart=Never -- sleep 3600
kubectl -n soc-lab exec -it soc-toolbox -- wget -qO- http://soc-demo-web

Clean up

kubectl -n soc-lab delete pod soc-toolbox
kubectl -n soc-lab delete service soc-demo-web
kubectl -n soc-lab delete deployment soc-demo-web
Safety note: Keep test events benign. You can learn triage, validation, and documentation without simulating real compromise behavior.

Check your understanding

Use these questions to check whether the lab and analyst concepts are clear before moving forward.

  1. What is the goal of safe test events?
  2. Why avoid exploit-style activity?
  3. What namespace hosts demo activity?
  4. What does kubectl exec do?
  5. Why record the time of your test?
  6. What should you compare in Wazuh?
  7. Why clean up demo workloads?
  8. What makes an event useful for training?
  9. What is a false positive in this context?
  10. Why should test activity be documented?
Answer key
  1. To generate telemetry for investigation practice.
  2. To keep the lab safe and responsible.
  3. soc-lab.
  4. Runs a command inside a container/pod.
  5. To correlate activity with alerts.
  6. Timestamp, source, rule, severity, and full log.
  7. To avoid clutter and confusion.
  8. It is controlled, documented, and visible.
  9. An alert on benign/expected activity.
  10. So analysts know what was intentionally generated.
