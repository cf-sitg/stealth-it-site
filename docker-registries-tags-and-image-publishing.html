Concepts before commands

A registry is where images are stored and shared.

A full image name can include registry hostname, namespace, repository, and tag.

Publishing images is how local builds become available to other machines or platforms.

Field note: Do not just run the command. Read the output. Docker teaches you a lot through container names, IDs, ports, status, logs, image tags, and inspect output.

Hands-on lab

Build a local image

mkdir registry-lab
cd registry-lab
echo FROM nginx:1.27 > Dockerfile
docker build -t registry-lab-web:1.0 .

Retag for a registry

docker tag registry-lab-web:1.0 your-registry.example.com/training/registry-lab-web:1.0
docker images

Optional login and push

docker login your-registry.example.com
docker push your-registry.example.com/training/registry-lab-web:1.0

Only run this if you have a real registry and permission.

Clean up local tags

docker rmi registry-lab-web:1.0
docker rmi your-registry.example.com/training/registry-lab-web:1.0

Troubleshooting checks

  • Check command output instead of assuming success.
  • Use docker ps -a when something disappears.
  • Use docker logs for app output.
  • Use docker inspect for configuration details.
  • Clean up lab artifacts after testing.

Common mistakes

  • Skipping validation commands.
  • Using latest casually for repeatable work.
  • Leaving containers, volumes, or networks behind.
  • Copying secrets into files or images.
  • Confusing host paths with container paths.

Where this fits in real environments

In real environments, registries are tied to access control, vulnerability scanning, signed images, promotion workflows, and deployment pipelines.
