Docker Troubleshooting

Container Logs and Troubleshooting

Container troubleshooting starts with state, logs, inspect output, image names, commands, and ports.

Docker Field Notes · Hands-on Lab

First checks

Use docker ps, docker ps -a, docker logs, and docker inspect before guessing.

Common failures

Containers exit when their command completes or fails. Port errors often mean the host port is already in use.

Evidence

Inspect output shows ports, mounts, networks, environment variables, and command configuration.

Hands-on lab commands

docker ps
docker ps -a
docker run --name exits-lab busybox:latest sh -c "echo starting; echo done"
docker logs exits-lab
docker run --name bad-command-lab busybox:latest command-that-does-not-exist
docker logs bad-command-lab
docker run --name port-lab-1 -d -p 8085:80 nginx:latest
docker run --name port-lab-2 -d -p 8085:80 nginx:latest
docker inspect port-lab-1
docker stop port-lab-1
docker rm exits-lab bad-command-lab port-lab-1
Bottom line: This lesson builds the practical Docker foundation needed before moving into orchestrated Kubernetes workloads.
