Concepts before commands

A registry stores images. Docker Hub is a public example, but organizations often use private registries.

An image is made of layers and metadata. A container is created from that image and adds runtime state.

A tag is a human-friendly label. Tags are useful, but they are not the same thing as immutable version control unless your process treats them that way.

Field note: Do not just run the command. Read the output. Docker teaches you a lot through container names, IDs, ports, status, logs, image tags, and inspect output.

Hands-on lab

Step 1: Pull and list images

docker pull nginx:1.27
docker images

Step 2: Run a container from the image

docker run --name image-domain-lab -d -p 8082:80 nginx:1.27
docker ps

Step 3: Inspect image and container

docker image inspect nginx:1.27
docker inspect image-domain-lab
docker history nginx:1.27

Step 4: Retag locally

docker tag nginx:1.27 local-nginx-lab:1.0
docker images

Step 5: Clean up

docker stop image-domain-lab
docker rm image-domain-lab
docker rmi local-nginx-lab:1.0

Troubleshooting checks

  • If a pull fails, check the image name, tag, registry access, and internet connectivity.
  • If an image cannot be removed, check whether containers still reference it.
  • Use docker history to understand layer creation at a high level.

Common mistakes

  • Using latest everywhere.
  • Confusing image removal with container removal.
  • Assuming a tag never changes.
  • Pulling images from untrusted sources.

Where this fits in real environments

Real environments usually define approved registries, approved base images, tagging standards, scanning gates, and promotion rules from development to production.
