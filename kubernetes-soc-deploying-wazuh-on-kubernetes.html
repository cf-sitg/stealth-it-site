Important deployment note

This lesson anchors deployment to the official Wazuh Kubernetes documentation instead of copying a fixed manifest into this training page. Wazuh versions, image tags, credentials, services, and manifests can change. Use official Wazuh documentation as the source of truth for the current deployment procedure.

Operator note: Training content should explain what you are applying and how to validate it. The vendor documentation should remain the source of truth for current manifests and version-specific commands.

Deployment workflow

1. Review official Wazuh Kubernetes documentation.
2. Confirm lab CPU, memory, and storage.
3. Clone or obtain official Wazuh Kubernetes deployment manifests.
4. Review namespaces, secrets, storage, and service types before applying.
5. Apply the local Kubernetes deployment variant recommended by Wazuh.
6. Watch pods, services, and PVCs in the wazuh namespace.
7. Access the dashboard safely.
8. Change default credentials where required.
9. Document deployed version and cleanup steps.

Validation commands

kubectl get namespace wazuh
kubectl get all -n wazuh
kubectl get pods -n wazuh -o wide
kubectl get svc -n wazuh
kubectl get pvc -n wazuh
kubectl get secrets -n wazuh
kubectl get events -n wazuh --sort-by=.lastTimestamp

Troubleshooting deployment

  • Use kubectl describe pod for scheduling, mount, image pull, and readiness problems.
  • Use kubectl logs for container startup errors.
  • Use kubectl get pvc if pods are waiting on storage.
  • Use kubectl get events for chronological failure clues.
