Concepts before commands

Operators care about names, ports, logs, restart behavior, environment variables, resource boundaries, and cleanup.

A container command should be understandable. If a container exits, you should know whether it completed normally, failed, or was misconfigured.

Docker runtime flags are the local version of many concepts that later appear in Kubernetes Pod specs.

Field note: Do not just run the command. Read the output. Docker teaches you a lot through container names, IDs, ports, status, logs, image tags, and inspect output.

Hands-on lab

Step 1: Run with name, env, and port

docker run --name operator-nginx -d -p 8083:80 -e APP_ENV=lab nginx:1.27

Step 2: Inspect runtime settings

docker ps
docker inspect operator-nginx
docker exec -it operator-nginx /bin/sh -c "echo $APP_ENV"

Step 3: Test restart policy

docker run --name restart-lab -d --restart unless-stopped nginx:1.27
docker inspect restart-lab

Step 4: Test resource flags

docker run --name resource-runtime-lab -d --memory 256m --cpus 0.5 nginx:1.27
docker stats resource-runtime-lab

Press Ctrl+C to exit stats.

Step 5: Clean up

docker stop operator-nginx restart-lab resource-runtime-lab
docker rm operator-nginx restart-lab resource-runtime-lab

Troubleshooting checks

  • Use docker inspect for environment variables, restart policy, mounts, and ports.
  • Use docker stats for live resource usage.
  • Use docker ps -a to understand exited containers.
  • Use docker logs before removing evidence.

Common mistakes

  • Running unnamed containers and losing track of them.
  • Forgetting restart policies exist.
  • Using environment variables for real secrets in casual local labs.
  • Leaving test containers running and consuming ports.

Where this fits in real environments

Production platforms wrap runtime settings into declarative specs. Learning the flags locally makes Kubernetes resources easier to understand later.

What you just learned

  • Ran named containers with environment values.
  • Inspected restart and resource settings.
  • Used docker stats.
  • Cleaned up deliberately.
Bottom line: Docker skills are operational skills. You are learning how applications are packaged, started, connected, inspected, fixed, and safely removed.
