Docker Lab Setup

Setting Up a Local Docker Lab

Before learning Docker deeply, you need a safe place to build, run, inspect, break, and clean up containers. This lab starts from a Windows machine and walks through WSL 2, Ubuntu, Docker Desktop, Linux containers, Docker Compose, and your first test container.

Docker Field Notes · Foundation Level · Estimated reading time: 22 minutes

What this lab gives you

This lab sets up a local Docker environment on your own machine. The goal is not to build a production container platform. The goal is to create a safe practice environment where you can learn Docker commands, build images, run containers, inspect logs, test networks, use volumes, and clean up quickly.

For this series, the standard local Docker lab uses:

  • WSL 2 for Linux support on Windows
  • Ubuntu as the local Linux distribution
  • Docker Desktop using the WSL 2 backend
  • Linux containers
  • Docker CLI
  • Docker Compose
  • Visual Studio Code or another editor for Dockerfiles and Compose files
  • PowerShell or Windows Terminal
Field note: A good container lab is disposable. You should be able to run containers, break them, remove them, rebuild images, and clean up without worrying about damaging anything important.

Why start with Docker before Kubernetes?

Kubernetes schedules and manages containers, but it does not remove the need to understand containers. If you do not understand images, tags, ports, volumes, logs, networks, and container lifecycle, Kubernetes troubleshooting becomes much harder.

The first learning goal is simple:

  • Can you install Docker successfully?
  • Can Docker run Linux containers?
  • Can you pull an image?
  • Can you run a container?
  • Can you expose a container on a local port?
  • Can you inspect logs and container state?
  • Can you stop, remove, and rebuild safely?

Before you start

This walkthrough assumes you are using a Windows 10 or Windows 11 machine and may be starting without WSL 2, Ubuntu, or Docker Desktop already configured.

You should have:

  • A Windows machine that supports WSL 2
  • Local administrator rights
  • Internet access
  • PowerShell or Windows Terminal
  • Enough disk space for Docker images, containers, and volumes

If you are using a corporate-managed device, installation may be blocked by endpoint policy. In that case, you may need help from your desktop, endpoint, or IT support team.

Step 1: Open PowerShell as Administrator

Start by opening PowerShell with administrator rights.

  • Click Start.
  • Search for PowerShell.
  • Right-click it.
  • Select Run as administrator.

Step 2: Install WSL

Run this command from the administrator PowerShell window: 

wsl --install

This installs the Windows Subsystem for Linux components and enables the Windows features needed for WSL. On many systems, it also installs Ubuntu as the default Linux distribution. On some systems, it only installs the WSL components first and requires a reboot before Ubuntu is installed.

If Windows tells you that changes will not take effect until the system is rebooted, restart the machine before continuing. 

Restart-Computer

Step 3: Check whether a Linux distribution is installed

After rebooting, open PowerShell again and run: 

wsl -l -v

If Ubuntu installed successfully, you should see a distribution listed with version 2. 

  NAME      STATE           VERSION
* Ubuntu    Stopped         2

If you see a message that WSL has no installed distributions, that is okay. It means WSL is enabled, but no Linux distribution has been installed yet.

Step 4: List available Linux distributions

To see which Linux distributions are available, run: 

wsl --list --online

For this lab, we use Ubuntu because it is common, well documented, and works well with Docker Desktop and container tooling.

Step 5: Install Ubuntu

Install Ubuntu with: 

wsl --install -d Ubuntu

If Ubuntu is already installed, continue to the next step.

If you receive an error, run the online list command again and use the exact Ubuntu distribution name shown in your output. 

wsl --list --online
wsl --install -d Ubuntu-24.04

Step 6: Launch Ubuntu and finish first-run setup

Launch Ubuntu: 

wsl -d Ubuntu

Ubuntu should ask you to create a Linux username and password. These are for your local Linux environment and do not need to match your Windows username and password.

When Ubuntu setup finishes, exit the Linux shell: 

exit

Step 7: Confirm Ubuntu is running on WSL 2

Back in PowerShell, run: 

wsl -l -v

You should see Ubuntu listed with version 2.

If Ubuntu shows version 1, set WSL 2 as the default: 

wsl --set-default-version 2

Then convert Ubuntu to WSL 2: 

wsl --set-version Ubuntu 2

If your distribution name is different, use the exact name shown by wsl -l -v.

Step 8: Update Ubuntu packages

Open Ubuntu from the Start menu, or run: 

wsl -d Ubuntu

Inside Ubuntu, run: 

sudo apt update
sudo apt upgrade -y

When it finishes, return to PowerShell: 

exit

Step 9: Install Docker Desktop

Docker Desktop is the easiest Docker setup for this Windows-based lab. It provides the Docker engine, Docker CLI integration, Docker Compose, and the local container runtime environment.

From PowerShell, install Docker Desktop with winget: 

winget install Docker.DockerDesktop

If winget asks you to accept package terms or source agreements, accept them if they are appropriate for your machine.

After the install finishes, start Docker Desktop from the Windows Start menu.

Docker may ask you to log out, reboot, or accept its service agreement. Follow the prompts.

Step 10: Enable Docker Desktop's WSL 2 backend

Open Docker Desktop and check these settings:

  • Go to Settings.
  • Go to General.
  • Make sure Use the WSL 2 based engine is enabled if the option is visible.
  • Go to Resources.
  • Go to WSL Integration.
  • Enable integration with your Ubuntu WSL distribution.
  • Select Apply & Restart if Docker prompts you.

On some current Docker Desktop installations, the WSL 2 engine is enabled automatically when the system supports WSL 2, and the setting may not be visible. The important part is that Docker Desktop is running with WSL 2 support and Ubuntu integration is enabled.

Field note: For this lab, Docker needs to run Linux containers. Most Docker and Kubernetes labs use Linux container images.

Step 11: Confirm Docker is working

Open a new PowerShell window and run: 

docker version

Then run: 

docker ps

The first command checks whether the Docker client and server are responding. The second command lists running containers. It is okay if no containers are running yet.

If this fails

  • Start Docker Desktop.
  • Confirm Docker Desktop is using the WSL 2 backend.
  • Confirm Docker Desktop is using Linux containers.
  • Confirm WSL integration is enabled for Ubuntu.
  • Close and reopen PowerShell after installing Docker.
  • Restart Docker Desktop if the Docker engine is not responding.

Step 12: Confirm Docker Compose is available

Docker Desktop normally includes Docker Compose. Confirm it: 

docker compose version

You should see Docker Compose version information.

Field note: Use docker compose with a space for modern Docker Compose. Older examples online may show docker-compose with a hyphen.

Step 13: Run your first test container

Run nginx and publish it on local port 8080: 

docker run --name docker-lab-nginx -d -p 8080:80 nginx:latest

Open: 

http://localhost:8080

You should see the nginx welcome page.

What this command does

  • docker run starts a container.
  • --name docker-lab-nginx gives the container a readable name.
  • -d runs it in the background.
  • -p 8080:80 maps host port 8080 to container port 80.
  • nginx:latest is the image Docker uses.

Step 14: List running containers

Run: 

docker ps

You should see docker-lab-nginx running.

Step 15: View container logs

Run: 

docker logs docker-lab-nginx

Refresh the browser and run the logs command again. You should see access log entries from nginx.

Step 16: Inspect the container

Run: 

docker inspect docker-lab-nginx

The output is long. For now, notice that Docker knows the image, container ID, network settings, port mappings, mounts, environment variables, and runtime configuration.

Step 17: Exec into the container

Run: 

docker exec -it docker-lab-nginx /bin/sh
hostname
ps
ls /usr/share/nginx/html
exit

This lets you inspect inside the running container. Do not get into the habit of manually fixing containers from the inside. Containers should be rebuilt or recreated from images.

Step 18: Stop and remove the test container

Stop the container: 

docker stop docker-lab-nginx

Remove it: 

docker rm docker-lab-nginx

Confirm no containers are running: 

docker ps

Confirm the stopped container is gone: 

docker ps -a

Step 19: Confirm the image still exists

Removing a container does not remove the image. Run: 

docker images

You should still see the nginx image.

You can remove the image if you want: 

docker rmi nginx:latest

Step 20: Run a quick Compose test

Create a temporary folder: 

mkdir docker-compose-smoke-test
cd docker-compose-smoke-test

Create a file named compose.yaml: 

services:
  web:
    image: nginx:latest
    ports:
      - "8081:80"

Start it: 

docker compose up -d

Check it: 

docker compose ps

Open: 

http://localhost:8081

Clean it up: 

docker compose down
cd ..

Common setup problems

WSL installed but no Linux distributions are listed

WSL is enabled, but Ubuntu has not been installed yet. 

wsl --list --online
wsl --install -d Ubuntu

Ubuntu does not show version 2

Check the distribution name: 

wsl -l -v

Then set that distribution to WSL 2: 

wsl --set-version Ubuntu 2

Docker is not running

Check: 

docker version
docker ps

If the Docker server is not responding, start Docker Desktop and wait for the engine to finish starting.

Docker is in Windows container mode

Switch Docker Desktop to Linux containers. This is usually available from the Docker Desktop tray icon or Docker Desktop settings.

Docker WSL integration is not enabled

Open Docker Desktop and check:

  • Settings
  • Resources
  • WSL Integration
  • Enable integration for Ubuntu

PowerShell does not recognize docker

Close and reopen PowerShell. If that does not work, restart the machine and confirm Docker Desktop installed successfully.

Port 8080 is already in use

Use a different host port: 

docker run --name docker-lab-nginx -d -p 8082:80 nginx:latest

Then browse to: 

http://localhost:8082

What this lab is good for

  • Learning Docker CLI basics
  • Running and inspecting containers
  • Testing Docker images
  • Practicing port mappings
  • Learning logs and troubleshooting
  • Using Docker Compose for repeatable local labs

What this lab is not good for

  • Production hosting
  • Multi-node orchestration
  • Enterprise registry governance
  • Production secret management
  • Cloud load balancer or Kubernetes behavior

Those topics come later. The point of this lab is to build container muscle memory before adding orchestration complexity.

Quick lab checklist

Before moving to the next lesson, make sure you can run each of these successfully: 

wsl -l -v
wsl --list --online
wsl -d Ubuntu
docker version
