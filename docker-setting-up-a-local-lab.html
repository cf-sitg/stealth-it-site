Build a safe local Docker environment with WSL 2, Ubuntu, Docker Desktop, Linux containers, Docker Compose, and a first test container.

What this lab gives you

This lab sets up a local Docker environment on a Windows machine. The goal is not production hosting. The goal is a safe place to build, run, inspect, break, and clean up containers without risking important systems.

For this series, the standard local lab uses WSL 2, Ubuntu, Docker Desktop, Linux containers, Docker CLI, Docker Compose, PowerShell or Windows Terminal, and a text editor such as Visual Studio Code.

Field note: A good lab is disposable. You should be able to run containers, break them, remove them, rebuild images, and clean up without worrying about damaging anything important.

Before you start

  • A Windows 10 or Windows 11 machine that supports WSL 2
  • Local administrator rights
  • Internet access
  • PowerShell or Windows Terminal
  • Enough disk space for Docker images, containers, and volumes

Step 1: Open PowerShell as Administrator

Click Start, search for PowerShell, right-click it, and select Run as administrator.

Step 2: Install WSL

wsl --install

If Windows asks for a reboot, restart before continuing. 

Restart-Computer

Step 3: Check whether Ubuntu is installed

wsl -l -v

If no distribution is installed, list available distributions and install Ubuntu. 

wsl --list --online
wsl --install -d Ubuntu

If your list shows a versioned name, use the exact name shown, such as Ubuntu-24.04.

Step 4: Launch Ubuntu and finish first-run setup

wsl -d Ubuntu

Create the Linux username and password when prompted, then exit. 

exit

Step 5: Confirm Ubuntu is using WSL 2

wsl -l -v

If Ubuntu shows version 1, convert it. 

wsl --set-default-version 2
wsl --set-version Ubuntu 2

Step 6: Update Ubuntu packages

wsl -d Ubuntu
sudo apt update
sudo apt upgrade -y
exit

Step 7: Install Docker Desktop

winget install Docker.DockerDesktop

Start Docker Desktop from the Start menu. Follow any prompts to reboot, accept the service agreement, or finish setup.

Step 8: Enable WSL 2 backend and Ubuntu integration

  • Open Docker Desktop.
  • Go to Settings.
  • Check General for WSL 2 based engine if the option is visible.
  • Go to Resources and then WSL Integration.
  • Enable integration for Ubuntu.
  • Apply and restart Docker Desktop if prompted.
Field note: For this lab, Docker should run Linux containers. If Docker is in Windows container mode, switch to Linux containers.

Step 9: Confirm Docker is working

docker version
docker ps

It is okay if no containers are running. What matters is that Docker responds without an engine error.

Step 10: Confirm Docker Compose is available

docker compose version

Use the modern docker compose command with a space. Older examples may use docker-compose with a hyphen.

Step 11: Run your first container

docker run --name docker-lab-nginx -d -p 8080:80 nginx:latest

Open: 

http://localhost:8080

You should see the nginx welcome page.

Step 12: Inspect the running container

docker ps
docker logs docker-lab-nginx
docker inspect docker-lab-nginx

Step 13: Exec into the container

docker exec -it docker-lab-nginx /bin/sh
hostname
ps
ls /usr/share/nginx/html
exit

This is useful for inspection. Do not build habits around manually fixing containers from the inside. Containers should be recreated from images.

Step 14: Stop and remove the test container

docker stop docker-lab-nginx
docker rm docker-lab-nginx
docker ps
docker ps -a

Step 15: Run a quick Compose smoke test

mkdir docker-compose-smoke-test
cd docker-compose-smoke-test

Create compose.yaml: 

services:
  web:
    image: nginx:latest
    ports:
      - "8081:80"

Start and test it: 

docker compose up -d
docker compose ps

Open http://localhost:8081, then clean up. 

docker compose down
cd ..

Common setup problems

  • WSL installed but no distro exists: run wsl --list --online and install Ubuntu.
  • Ubuntu shows WSL version 1: convert it with wsl --set-version Ubuntu 2.
  • Docker server not responding: start Docker Desktop and wait for the engine.
  • Docker is in Windows container mode: switch to Linux containers.
  • PowerShell does not recognize docker: close and reopen PowerShell, or restart after install.
  • Port already in use: change the host port, such as -p 8082:80.

Answer key
  1. WSL 2 provides Linux support that Docker Desktop can use on Windows.
  2. Ubuntu provides a local Linux distribution for Linux-based tooling and WSL integration.
  3. Most images used in these labs are Linux container images.
  4. It confirms the Docker client and server are installed and responding.
  5. Running containers.
  6. It confirms the Compose plugin is available.
  7. Host port 8080 forwards to container port 80.
  8. An image is the packaged source; a container is a running instance of that image.
  9. No.
  10. You can experiment, break things, remove them, and rebuild without risk.
  11. Start Docker Desktop, wait for the engine, and confirm WSL/Linux container settings.
