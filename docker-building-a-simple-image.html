What this lesson covers

This lesson builds a custom image from a simple web page so you can see how source files become a runnable container image.

The short version

Building a Simple Image
  Practical goal:
    Understand the Docker concept.

    Inspect the result.

Concepts before commands

Building an image packages application content and instructions into a reusable artifact.

The Dockerfile describes how the image is assembled.

The build context is the folder Docker can use during the build.

Field note: Do not just run the command. Read the output. Docker teaches you a lot through container names, IDs, ports, status, logs, image tags, and inspect output.

Hands-on lab

Step 1: Create folder

mkdir docker-simple-image-lab
cd docker-simple-image-lab

Step 2: Create index.html

<!DOCTYPE html>
<html>
<body>
  <h1>Docker Simple Image Lab</h1>
  <p>This page is served from a custom Docker image.</p>
</body>
</html>

Save this as index.html.

Step 3: Create Dockerfile

FROM nginx:1.27
COPY index.html /usr/share/nginx/html/index.html
EXPOSE 80

Step 4: Build and run

docker build -t stealth-simple-web:1.0 .
docker run --name stealth-simple-web-lab -d -p 8084:80 stealth-simple-web:1.0

Open http://localhost:8084.

Step 5: Inspect and clean up

docker images
docker logs stealth-simple-web-lab
docker history stealth-simple-web:1.0
docker stop stealth-simple-web-lab
docker rm stealth-simple-web-lab

Troubleshooting checks

  • Check command output instead of assuming success.
  • Use docker ps -a when something disappears.
  • Use docker logs for app output.
  • Use docker inspect for configuration details.
  • Clean up lab artifacts after testing.

Common mistakes

  • Skipping validation commands.
  • Using latest casually for repeatable work.
  • Leaving containers, volumes, or networks behind.
  • Copying secrets into files or images.
  • Confusing host paths with container paths.

Where this fits in real environments

Real build pipelines automate these steps, tag images consistently, scan them, and push them to registries for later deployment.
