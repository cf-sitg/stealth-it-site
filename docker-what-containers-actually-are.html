Concepts before commands

A container is a running process created from an image. It has an isolated filesystem view, environment, process space, and network configuration, but it does not include a full guest operating system.

Containers are often called lightweight virtual machines, but that phrase can create the wrong mental model. A virtual machine virtualizes hardware and runs a full guest operating system. A container uses the host kernel and isolates the application process.

Docker provides the local tooling to pull images, create containers, start and stop containers, inspect metadata, attach ports, view logs, and remove resources.

Field note: Do not just run the command. Read the output. Docker teaches you a lot through container names, IDs, ports, status, logs, image tags, and inspect output.

Hands-on lab

Step 1: Run nginx

docker run --name container-model-lab -d -p 8080:80 nginx:latest

Open http://localhost:8080.

Step 2: Inspect process and logs

docker ps
docker logs container-model-lab
docker inspect container-model-lab

Step 3: Exec inside

docker exec -it container-model-lab /bin/sh
hostname
ps
ls /
exit

Step 4: Clean up

docker stop container-model-lab
docker rm container-model-lab

Troubleshooting checks

  • Use docker ps to confirm whether the container is running.
  • Use docker ps -a if the container exited.
  • Use docker logs to view application output.
  • Use docker inspect to confirm ports, image, command, and network settings.

Common mistakes

  • Thinking a container is a full virtual machine.
  • Manually changing running containers instead of rebuilding images.
  • Forgetting to remove stopped containers after labs.
  • Assuming localhost inside a container means the Docker host.

Where this fits in real environments

In real environments, containers are treated as disposable runtime units. You build or pull an image, run it with controlled configuration, collect logs externally, and replace it instead of manually maintaining it.

Bottom line: Docker skills are operational skills. You are learning how applications are packaged, started, connected, inspected, fixed, and safely removed.
