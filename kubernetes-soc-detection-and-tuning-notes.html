When to write a tuning note

  • The alert fires on expected lab activity.
  • The alert has useful intent but too much noise.
  • The alert lacks enough context for analysts.
  • The detection is correct but severity feels wrong.
  • The same benign pattern repeats frequently.

Do not tune blindly

Tuning should be evidence-based. Do not suppress an alert just because it is annoying. First understand the source, rule, pattern, affected systems, and risk.

Example tuning note

Detection name: Test shell execution in soc-lab
Purpose: Identify interactive command execution in monitored lab workloads
Data source: Wazuh agent telemetry from Kubernetes lab node
Expected behavior: Instructor-generated lab commands during scheduled exercises
Suspicious behavior: Unplanned shell execution in application workloads
Known false positives: Training exercises using kubectl exec
Tuning recommendation: Add lab namespace context to analyst notes; do not suppress globally
Validation steps: Compare timestamp with lab exercise log
Status: Monitor
Analyst note: Good tuning preserves useful signal while reducing unnecessary noise. Bad tuning hides risk.

Check your understanding

Use these questions to check whether the lab and analyst concepts are clear before moving forward.

  1. What is a detection note?
  2. What is a tuning note?
  3. Why should tuning be evidence-based?
  4. Why not suppress globally too quickly?
  5. What is a false positive?
  6. What is expected behavior?
  7. What is suspicious behavior?
  8. Why track data source?
  9. Why include validation steps?
  10. What is the risk of bad tuning?
Answer key
  1. A document explaining the purpose and logic of an alert/detection.
  2. A recommendation to improve alert quality or reduce noise.
  3. To avoid hiding real risk.
  4. It may remove useful signal from other contexts.
  5. An alert on benign/expected activity.
  6. Normal or approved activity.
  7. Activity that is abnormal, unauthorized, or risky.
  8. To know where telemetry comes from.
  9. To prove the note can be tested.
  10. It can hide incidents or create blind spots.
