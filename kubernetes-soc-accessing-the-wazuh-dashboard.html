Dashboard Access

Accessing the Wazuh Dashboard Safely

Access the Wazuh dashboard safely in a local lab using port-forwarding, then understand how production access differs.

Kubernetes SOC Field Lab · Practical Security Operations

Domain alignment

SIEM OperationsPlatform Operations

Lab objective

Access the Wazuh dashboard safely in a local Kubernetes lab. Start with port-forwarding so the dashboard is not broadly exposed.

Step 1: Find dashboard service

kubectl get svc -n wazuh

Step 2: Port-forward the dashboard

kubectl port-forward -n wazuh svc/<dashboard-service-name> 5601:5601

Open https://localhost:5601 or the URL/port indicated by your deployment. Local certificates may trigger a browser warning in a lab.

Step 3: Login and validate

  • Confirm you can log in.
  • Confirm Wazuh loads without server connection errors.
  • Confirm agents or platform components appear where expected.
  • Confirm alerts/search views are reachable.

Why not expose it broadly?

The dashboard is a sensitive SOC interface. In production, access should be protected with strong authentication, TLS, network controls, role-based access, logging, and operational ownership.

Security note: Do not publish the dashboard to the internet from a lab. Learning access control is part of SOC lab discipline.

Answer key
  1. It limits exposure in a local lab.
  2. kubectl get svc -n wazuh.
  3. kubectl port-forward -n wazuh svc/ local:remote.
  4. It exposes security monitoring data and administrative functions.
  5. Strong auth, TLS, network restrictions, RBAC, logging, and ownership.
  6. Local/self-signed lab certificates.
  7. Login, component connection, agents, alerts, and searches.
  8. To avoid unnecessary risk.
  9. Production-grade access security.
  10. So future operators know how the dashboard was accessed and secured.
